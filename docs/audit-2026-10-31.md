# JournalPro audit — 31 October 2026

## Result and scope

23 automated suites: 593/593 checks passed on Windows with Node 24.22.1. TypeScript checking, frontend production compilation, backend bundling, and diff whitespace checks passed. A separate real-HTTP flow verified profile edits, avatar/settings changes, logout/login, restart, two-tenant trade retention, tenant isolation, and durable trade deletion.

Tests used fresh temporary local databases and fake payment/worker credentials. Production records, real payments and broker accounts were not modified. This is a local source audit, not a guarantee that all production behavior is bug-free. The refreshed CI configuration has not been executed by GitHub Actions yet (CI uses Node 22/Linux).

## Confirmed issues fixed

1. **Local restart data loss:** generic saves updated memory without persisting user portfolios/trades. Added tenant-scoped file persistence while preserving other users and payment history. Confirmed by a failing restart test before the fix and passing two-user restart/deletion tests afterward. Local files still require persistent disk and a single application process; they are not a substitute for a shared production database.
2. **MT5 local worker job duplication:** once jobs are persisted, the file snapshot and cached copy could offer the same pending job to two workers. Queue enumeration now uses one authoritative live database per tenant, and restores persisted jobs/deals after restart. All 53 VPS-worker API checks pass, including lease ownership, replay prevention and worker authentication. No real MT5 terminal was involved.
3. **Production startup guard bypass:** the error for missing database credentials was swallowed by a catch that matched an older error message. The server now aborts instead of silently continuing on temporary file storage. Production-mode tests also confirm weak-secret rejection and that development header identity, debug endpoints and test billing stay disabled.
4. **Security dependencies:** compatible updates plus removal of the unused legacy Better Auth CLI reduced npm audit findings from 27 (3 critical, 8 high, 15 moderate, 1 low) to 8 moderate, with zero high/critical findings in the installed tree. The removed CLI carried an obsolete vulnerable auth copy; the app retains its runtime auth dependency and programmatic migration command.
5. **Broken self-hosted start command:** start referenced dist/server.cjs, while build emits api/server.bundled.js. The start command now matches that build output. Both frontend and server bundle compilation pass; a deployed self-hosted startup was not verified.
6. **Broken CI step:** CI called a missing check:migrations script. Removed that invalid step and replaced the ad-hoc shared dev server/two-test workflow with the isolated full audit runner. SQL migration execution against a real database remains unverified.
7. **Unreliable tests:** app.test.mjs reported failures but exited successfully; fixed its failure status. Updated obsolete demo-balance expectations, manual-account plan expectations, and invalid cloud payload expectations. The profile escalation test now calls the actual update-profile route rather than passing on a 404. Audit rejects skipped tests and FAIL output, and disables test billing for normal security suites.
8. **Repeatable verification:** npm run test:audit creates fresh isolated servers/stores, checks all suites without stopping at the first failed suite, captures results, and exits unsuccessfully if any suite fails. Profile Pro retention tests from the preceding fix are included.

## Remaining issues / follow-up

1. **8 moderate npm advisories remain:** ExcelJS and its archiver/glob/uuid dependency chain. These represent propagated dependency findings, not eight independently confirmed exploitable application paths. Root advisories are minimatch glob amplification (GHSA-g3hv-75wg-m249) and uuid buffer bounds (GHSA-w5hq-g745-h8pq). npm proposes a breaking ExcelJS downgrade; it was not forced. A compatible export-library upgrade/replacement needs dedicated spreadsheet export verification.
2. **Frontend bundle size warning:** main JS is about 1.67 MB uncompressed / 358 KB gzip; ExcelJS chunk is about 940 KB / 271 KB gzip. This is a build warning and potential loading-cost issue, not a measured performance failure. Real-device loading and route splitting are follow-up work.
3. **Visual/mobile QA incomplete:** the computer-use tool stopped because it could not confidently identify the active browser URL for policy enforcement. No assertion is made about responsive layout, click targets, visual overflow, browser console or authenticated UI rendering.
4. **Live integration checks remain:** payment capture/refund/settlement and webhook delivery from the provider; Google OAuth and delivered email; real broker compatibility, investor-password login and MT5 reconnect; production database roles, SQL migrations, backups and restore. Local API tests use synthetic signed events and mock deal payloads, not live providers.
5. **Deployment unverified:** these audit fixes are currently local, not committed/pushed/deployed. The earlier profile fix was pushed separately. No live rollout or production incident monitoring was performed for this audit batch.
